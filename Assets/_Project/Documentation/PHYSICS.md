# PHYSICS — физическая модель Фазы 1

## 1. Единицы

Все внутренние величины — СИ, `double`: м, с, кг, м/с, м/с², Н, Дж, Па, К. Интерфейс только округляет при выводе
(`UnitFormatter`). Перевод в `float` происходит один раз — при передаче в Unity для отрисовки (`CoordinateSystem`).

Константы (`PhysicalConstants`): G = 6.67430·10⁻¹¹ м³/(кг·с²), g₀ = 9.80665 м/с² (только как единица),
R_газ = 8.314462618 Дж/(моль·К), а. е. = 1.495978707·10¹¹ м. Параметры планет — **не** константы, а данные `PlanetDefinition`.

## 2. Системы координат

- **Инерциальная** (физика): правая, начало в центре планеты, Z — северный полюс эклиптики, X — направление на Солнце
  (Солнце в Фазе 1 неподвижно в этой системе). Все интегрирования выполняются здесь.
- **Связанная с планетой**: Z — ось вращения, X — нулевой меридиан. Переход: R(t) = R_x(наклон)·R_z(φ₀ + ω·t) (`PlanetRotation`).
- **Unity**: левая, float. Отображение `unity = (x, z, y)` — перестановка осей (отражение) корректно меняет рукость;
  кватернион → (−x, −z, −y, w); у треугольников меняется порядок обхода (`CoordinateSystem`).
- **Floating origin** (`FloatingOrigin`): точка в double, которая соответствует (0,0,0) Unity. Держится у камеры
  (сдвиг при удалении > 2 км). Все объекты каждый кадр получают позу из double, поэтому сдвиг ничего не «перетаскивает».
  Без этого шаг представимых float на расстоянии 6.4·10⁶ м ≈ 0.5 м — дрожание у камеры.

**Ограничение текущей архитектуры:** инерциальная система привязана к центру одной планеты (геоцентрическая).
Для межпланетных полётов планете нужна эфемерида (`PlanetModel.Position` сейчас статичен, гравитация уже суммируется
в `GravityField`), а начало системы — в барицентре; Unity-сторона от этого не меняется, т. к. всё проходит через double → origin.

## 3. Гравитация (`PlanetaryGravity`, `GravityField`)

```
F = G·M·m / r²        g(r) = μ / r²        a⃗ = −μ · r⃗ / |r⃗|³
```

r⃗ — от центра планеты к телу. Ускорение не зависит от массы тела и от визуального состояния/камеры.
`Physics.gravity` и Rigidbody **не используются**.

Допущения: сферически-симметричная планета (точечная масса — точное решение вне шара); **не учитываются** сплюснутость (J2),
неоднородности поля, приливы, релятивистские поправки. Вращение планеты на гравитационное поле не влияет;
центробежный эффект появляется естественно, т. к. движение считается в инерциальной системе.
Внутри шара (недостижимо при штатной работе) — линейный закон, чтобы не делить на ноль.

## 4. Движение и интегрирование (`NumericalIntegrator`, `FreeFlightSimulation`, `SimulationClock`)

**Velocity Verlet** (по умолчанию):

```
x₁ = x₀ + v₀Δt + ½a₀Δt²
a₁ = a(x₁, v*),   v* = v₀ + a₀Δt   (предиктор — только для сил, зависящих от скорости)
v₁ = v₀ + ½(a₀ + a₁)Δt
```

Почему не Эйлер: явный Эйлер не симплектичен — энергия на орбите растёт каждый оборот (тест: ошибка > 10⁻³ за виток при Δt = 1 с,
в > 1000 раз хуже Verlet). Verlet для консервативных сил симплектичен и обратим во времени: ошибка энергии ограничена
(колеблется с амплитудой ~(ωΔt)²) и не дрейфует. Ограничения: второй порядок — фазовая (вдоль орбиты) ошибка растёт линейно
со временем; с сопротивлением метод перестаёт быть симплектичным (сопротивление и так диссипативно); RK4 доступен для сравнения.

**Шаг**:
- Фиксированный шаг симуляции Δt = 0.02 с (настраивается), часы-аккумулятор: результат **не зависит от FPS** —
  тест прогоняет одно и то же при 60, 144 FPS и случайных кадрах 4–90 мс и получает побитово одинаковое состояние.
- Время симуляции = номер шага × Δt (без накопления ошибки суммирования).
- Автоматическое дробление шага: Δt ≤ η·√(r³/μ) (η = 0.002, ≈3100 шагов на виток) и Δt ≤ 0.05·v_rel/|a_drag|.
- Ускорение времени ×1…×1000; если за кадр нужно больше 5000 шагов, время замедляется (HUD показывает «ограничено»), а шаг не растёт.
- Интерполяция только для отрисовки: позиция между двумя последними шагами; в физику не возвращается.

**Контакт с поверхностью**: после каждого подшага проверяется высота над физической поверхностью; момент касания уточняется
бисекцией (24 итерации), фиксируется скорость удара относительно грунта. На грунте тело жёстко вращается с планетой
(v = ω × r) и стоит, пока игрок не задаст новые начальные условия. Отскока/разрушения пока нет.

**Проверено тестами**: время падения с 1 км совпадает с точным решением радиального падения до 10⁻⁴ с;
вертикальный выстрел 3 км/с достигает высоты из закона сохранения энергии (±2 м); круговая орбита держит радиус ±1 м
за 3 витка; через один период тело возвращается в исходную точку с точностью 5 см (Δt = 0.02 с);
порядок сходимости ≈ 2; падение в атмосфере выходит на предельную скорость ±1 %.

## 5. Атмосфера (`AtmosphericModel`, `AtmosphericDrag`, `AtmosphereOptics`)

Три **разных** параметра:

1. **Физическая плотность** ρ(h) — используется в сопротивлении и телеметрии. Никогда не обрывается.
2. **Визуальная оболочка** — радиус сферы, на которой рендерится рассеяние: высота, где ρ/ρ₀ = 10⁻⁶ (для Земли 117 км), либо задаётся вручную.
3. **Условная граница космоса** (100 км) — только уведомления и подсказки.

Модели плотности:
- экспоненциальная изотермическая: `ρ(h) = ρ₀·e^(−h/H)`, `p(h) = p₀·e^(−h/H)`, `T = T₀`;
- табличная: лог-линейная интерполяция ρ и p (точна для кусочно-экспоненциальных слоёв), линейная T,
  экспоненциальная экстраполяция за пределами таблицы.

Вспомогательно: `H = R·T / (M·g)` (для воздуха ≈ 8.4 км), `ρ = p·M / (R·T)`.

Ограничение экспоненциальной модели: выше ~90 км реальная атмосфера горячее и плотнее модели (в термосфере плотность
занижена на порядки). Для точного торможения на низких орбитах — табличная модель (например, по NRLMSISE/US Standard Atmosphere).

**Сопротивление**: `F⃗ = −½·ρ·|v⃗_rel|·v⃗_rel·Cd·A`, где `v⃗_rel = v⃗ − k·(ω⃗ × r⃗)` — скорость **относительно воздуха**
(k — коэффициент совместного вращения, 1 = без ветра). Не учитываются подъёмная сила, Cd(M, Re), нагрев, ветер.
Телеметрия: скоростной напор q = ½ρv², ускорение сопротивления.

**Свет** (для ламп и неба): спектральная прозрачность `T = exp(−∫(β_R·ρ/ρ₀ + β_M,ext·e^(−h/H_M)) ds)` вдоль луча на Солнце
(β_R = (5.8, 13.6, 33.1)·10⁻⁶ м⁻¹, β_M = 4.0·10⁻⁶ м⁻¹, H_M = 1.2 км, g = 0.8). Ноль в геометрической тени планеты.

## 6. Классификация фазы полёта (`FlightStateClassifier`)

Только для интерфейса и подсказок: не меняет физику и не блокирует движение.

| Условие | Фаза |
|---|---|
| на грунте | Ground |
| h ≥ границы (или нет атмосферы) и ε ≥ 0 | EscapeTrajectory |
| h ≥ границы, ε < 0, перицентр ≤ max рельефа | Spaceflight (или Landing при снижении у поверхности) |
| h ≥ границы, ε < 0, перицентр < 140 км (есть атмосфера) | Spaceflight (орбита разрушится сопротивлением) |
| h ≥ границы, ε < 0, перицентр выше порога | OrbitalFlight |
| h < границы, снижение, высота над поверхностью < 2 км | Landing |
| h < границы, ρ/ρ₀ < 0.01 | UpperAtmosphere |
| h < границы, v_up > +1 м/с / < −1 м/с | AtmosphericAscent / AtmosphericDescent (гистерезис) |

Перицентр: `r_p = (h²/μ)/(1 + e)` — устойчиво для любых коник. ε < 0 само по себе **не** считается орбитой.

## 7. Телеметрия (`FlightTelemetry`)

h над поверхностью и над R, r, широта/долгота, |v| инерциальная / относительно поверхности / относительно воздуха,
v_r, горизонтальная скорость, вектор скорости (ENU относительно поверхности и инерциальные компоненты), g(r),
полное ускорение, перегрузка (показание акселерометра: 0 в свободном полёте, ≈1 g₀ на грунте), ρ, ρ/ρ₀, p, T, q,
ускорение сопротивления, ε, оскулирующие элементы (e, a, r_p, r_a, T, i), v_круг и v_уход в текущей точке,
грубая оценка времени до контакта `t = (v_r + √(v_r² + 2gh))/g` (постоянное g, без сопротивления и кривизны;
не выводится, если перицентр выше рельефа).

## 8. Визуализация, не влияющая на физику

- Атмосфера: однократное рассеяние Рэлея + Ми, ray-marching (16×8 выборок) на оболочке с отсечением передних граней —
  один и тот же расчёт с земли, из стратосферы и с орбиты, поэтому скачков нет. Длина луча ограничена буфером глубины и сферой планеты.
  Композиция: `цвет = рассеянный_свет + сцена × T_ср` — голубое небо, дымка над далёким рельефом, тонкая оболочка с орбиты, гашение звёзд.
  Упрощения: одна (средняя) прозрачность для сцены (нет спектрального покраснения далёких объектов), одна шкала высот для
  Рэлея (для табличных профилей — эффективная по плотности на 5 км), нет многократного рассеяния и озона.
- Поверхность: собственная прозрачность к Солнцу по воздушной массе (Kasten–Young), геометрический терминатор, тени URP вблизи камеры.
- Звёзды: детерминированный каталог 9000 звёзд в инерциальной системе; видимость = адаптация глаза к яркости неба
  (доля столба воздуха над камерой × освещённость), а не физический процесс.
- Камера: ограничения (не ниже 1.6 м над грунтом) и плоскости отсечения — только визуальные.

## 9. Будущая модель двигателей и топлива (не реализована)

Расход топлива в Фазе 1 не моделируется и не изображается. План для следующих фаз:

- тяга F [Н] (вектор в связанной с аппаратом системе), удельный импульс I_sp [с] (возможно, зависящий от давления: I_sp(p) между вакуумным и на уровне моря);
- массовый расход `ṁ = F / (I_sp · g₀)` [кг/с], g₀ = 9.80665 м/с² — константа-единица;
- переменная масса `m(t) = m_сухая + m_топлива(t)`; ускорение `a⃗ = F⃗/m + a⃗_грав + a⃗_сопр`; интегрирование массы вместе с состоянием
  (тяга не консервативна → RK4 или Verlet с малым шагом на участках работы двигателя, переход на Verlet на баллистике);
- проверочное соотношение — формула Циолковского `Δv = I_sp·g₀·ln(m₀/m_к)` (тест: импульсный манёвр в вакууме должен её воспроизводить);
- потери: гравитационные `∫ g·sin γ dt`, аэродинамические `∫ D/m dt` — в телеметрию для обучения;
- ограничения: дросселирование, время запуска, предельные перегрузки и q, расход окислителя/горючего по соотношению компонентов.
