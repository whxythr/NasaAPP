# PROCEDURAL_GENERATION — генерация, seed и воспроизводимость

## Принципы

1. Поверхность — **детерминированная функция** `направление (связанная с планетой система) → высота, биом, цвет`
   (`PlanetSurfaceSampler`). Она зависит только от `PlanetGenerationSettings` (включая `seed`), версии алгоритма и физического радиуса.
2. Нет ни одного вызова `UnityEngine.Random`/`System.Random` и ничего, зависящего от времени: случайность — только
   `DeterministicRandom` (SplitMix64, целочисленная арифметика, проверка по эталонной последовательности в тестах).
3. Шум — собственный градиентный 3D-шум Перлина (2002) в `double` с перестановкой, перемешанной по seed. Вычисления в горячем пути —
   только `floor`, `+`, `−`, `×`, `/`, `sqrt` (детерминированы по IEEE-754). 3D-выборка на единичной сфере — без швов и полюсных артефактов.
4. Каждая подсистема получает собственный поток: `Mix(seed, соль)` (варп, континенты, горы, маска гор, детали, влажность, климат, кратеры).
5. Визуальный seed **не меняет** массу, радиус и гравитацию: физика хранится отдельно (`PlanetPhysicalProperties`).
   Физические параметры новых миров генерирует отдельный `PlanetPhysicalGenerator` (свой seed, своя версия) один раз — затем они хранятся как данные.
6. Поверхность никогда не генерируется целиком и не пересчитывается каждый кадр: чанки строятся по требованию и кэшируются.

## Алгоритм версии 1

```
q    = p + warp(p)                                         доменное искажение (3 × fBm)
c    = fBm(q · f_cont) + bias                              континенты; c < 0 — океанское дно
h    = c · A_land  (c ≥ 0)   или   c · A_ocean (c < 0)
h   += ridged(q · f_mount)² · A_mount · маска(c, шум)      горные хребты только на суше
h   += fBm(q · f_detail) · A_detail                        мелкий рельеф (9 октав, до ~60 м)
h   += Σ кратеры                                           чаша + вал из smooth min/max (ровно 0 за валом)
h    = lerp(h, h_зоны, w)                                  выравнивание зон (стартовая площадка)
поверхность = max(h, уровень моря)                         океан — плоская поверхность для физики и графики
```

Биомы: «климат» = 1 − sin²φ ± шум − охлаждение с высотой; влажность — fBm. Плавные смеси: луга → лес / пустыня → тундра → скалы → снег,
пляжи у берега, морской лёд у полюсов. Тип биома доступен в `SurfaceSample.Biome`.

Обычный шум не гарантирует геологически правдоподобный рельеф (нет тектоники и эрозии) — это осознанное упрощение;
версия 2 может добавить эрозию и плиты (см. ROADMAP).

## Геометрия и LOD

- **Cube-sphere** (`CubeSphere`): 6 граней куба, отображение «spherified cube» — равномернее нормализованного куба и без сжатия UV-сферы у полюсов.
  Координаты узлов — двоичные дроби, поэтому вершины общих рёбер граней **побитово совпадают** (тест), швов нет.
- **Квадродерево** (`ProceduralPlanetGenerator`): чанк делится, когда камера ближе `ребро × 2.2`; объединение с гистерезисом 15 %.
  Глубина до 14 уровней (≈ 19 м на квад на Земле). Родитель заменяется детьми только когда все четыре готовы — дыр не бывает.
- Нормали: внутри чанка — по соседям сетки; на краях — по конечным разностям в касательной системе ENU, не зависящей от грани
  (совпадают у соседних чанков — тест). Трещины между уровнями LOD закрыты «юбками».
- Отсечение: по горизонту (консервативно, по сфере минимальной поверхности) + штатное frustum culling Unity.
- **Разделение генерации и рендеринга**: `ChunkMeshBuilder` (чистый C#, фоновые потоки, ~8 мс на чанк 33×33) → очередь →
  загрузка в GPU не более N мешей за кадр.
- **Кэш**: LRU с бюджетом памяти (256 МБ по умолчанию); чанки, используемые деревом, не вытесняются.
- WebGL/без потоков: синхронный режим, 2 чанка за кадр.
- Позиция каждого чанка вычисляется в double от центра чанка — дрожания нет даже у поверхности.

## Сохранение и версии

`PlanetSaveData` (JSON через `JsonUtility`, `PlanetSaveService`):

| Поле | Назначение |
|---|---|
| `saveFormatVersion` | версия формата файла |
| `planetId`, `displayName`, `createdUtc` | идентичность |
| `surfaceAlgorithmVersion` | версия `PlanetSurfaceSampler`, которой создана поверхность |
| `physicalGeneratorVersion`, `physicalSeed` | откуда взялась физика (0 — задана вручную) |
| `generation` | все параметры генерации, включая `seed` и зоны выравнивания |
| `physical`, `optics` | физические и оптические параметры — хранятся, а не выводятся заново |
| `surfaceFingerprint` | FNV-1a-хеш 150 выборок (высота с точностью 1 см, цвет, биом) |
| `surfaceModifications` | заготовка для будущих изменений рельефа (не применяется в Фазе 1) |

Загрузка (`PlanetSaveValidator.Validate`):
1. формат новее, чем поддерживает сборка → отказ;
2. версия алгоритма не поддерживается → **отказ** (`UnsupportedAlgorithmVersion`), а не тихая генерация другой планеты;
3. поверхность регенерируется и сравнивается отпечаток → при расхождении отказ (`FingerprintMismatch`).

Правило развития: любое изменение, меняющее результат (соли, порядок октав, формулы), — новая версия алгоритма;
старая остаётся в коде (`IsAlgorithmVersionSupported`), пока существуют сохранения с ней.

Известная граница детерминизма: трансцендентные функции (`Exp`, `Log`, `Sin`, `Cos`) могут отличаться в последнем бите
между платформами/рантаймами. В горячем пути поверхности их нет (размеры кратеров — полином, направления — отбор в кубе + `sqrt`);
`sin/cos` используются только один раз при построении зон выравнивания из широты/долготы, а `Exp/Log` — в физическом генераторе,
результат которого сохраняется и не пересчитывается. Отпечаток квантуется до 1 см, поэтому различия в последнем бите на него не влияют.

## Как получить разные планеты

- В `Earth.asset` (или любом `PlanetDefinition`) поменяйте `generation.seed` — в Play mode поверхность перестроится сразу;
  в инспекторе есть *New random visual seed* и *Compute surface fingerprint*.
- Тот же seed + те же параметры + та же версия = тот же отпечаток (повторите *Compute surface fingerprint*).
- *SpaceSim ▸ Create Random Planet Definition* — новый ассет с сохранёнными визуальным и физическим seed.
- Ручная настройка: частоты/амплитуды континентов, гор, деталей, океан и уровень моря, число и размер кратеров, цвета биомов,
  оттенок атмосферы, параметр облачности (хранится для будущего слоя облаков).

## Импортированные модели (Blender)

`surfaceSource = ImportedModel`: префаб FBX/OBJ, радиус модели в её единицах, поправка поворота (+Y модели = север).
Модель масштабируется под **физический** радиус и вращается вместе с планетой; физическая поверхность — опорная сфера R.
Ограничения: одна огромная сетка подходит для вида с орбиты, но у поверхности даст float-дрожание (нет разбиения на чанки
с центрами в double) и не даёт высот для посадки — для этого используйте процедурный режим или (в будущем) импорт карты высот.
