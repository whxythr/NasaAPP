## 4. Центральная физическая архитектура

Один слой — `SpaceSim.Core`. Ниже — роли из ТЗ, сопоставленные с существующими/новыми типами ядра.

| Роль из ТЗ | Тип(ы) в ядре | Уровень |
|---|---|---|
| PhysicsManager | `FreeFlightSimulation` (+ `SimulationClock`) — единственный интегратор полёта | B |
| GravitySystem | `PlanetaryGravity`, `GravityField` | B |
| RocketPhysics / EnginePhysics / FuelSystem | `RocketState`, `RocketConfiguration`, **`RocketEquations`** (новый) | A + B |
| AtmosphericPhysics | `AtmosphericModel`, `AtmosphericDrag` | B |
| OrbitalMechanics | `OrbitalMechanics`, `KeplerOrbit` | A |
| TrajectoryCalculator | **`TransferCalculator`** (новый: Гоман, фазовый угол, окна, гиперболический выход) | A |
| — | **`RocketDesignAnalysis`** (новый: статистика конфигурации, предупреждения) | A |
| — | **`FlightRecorder`** (новый: потери Δv, максимумы, путь) | B |
| LandingPhysics | `FreeFlightSimulation` (контакт, скорость касания) + будущий `LandingAnalysis` | B (M6) |

### Два уровня расчётов

- **Level A — теория** (`RocketEquations`, `OrbitalMechanics`, `TransferCalculator`, `RocketDesignAnalysis`): идеальные формулы.
  Используются Академией, ангаром и планировщиком. Всегда подписываются в UI как «идеально / без потерь».
- **Level B — симуляция** (`FreeFlightSimulation` + `FlightRecorder`): то, что реально происходит в игре — гравитация, сопротивление,
  переменная масса, тяга(p), направление тяги, движение планет, численное интегрирование.
  UI показывает A и B рядом, например «Идеальный Δv: 13 045 м/с · Израсходовано: 4 210 м/с · Потери: гравитация 1 120, сопротивление 160».

### Общие интерфейсы (контракт для всех агентов)

```csharp
// Level A — чистые функции, СИ, без состояния
static class RocketEquations {
    double DeltaV(double isp, double m0, double mf);                 // Δv = Isp·g0·ln(m0/mf)
    double MassRatio(double deltaV, double isp);                     // m0/mf = exp(Δv/(Isp·g0))
    double PropellantForDeltaV(double deltaV, double isp, double finalMass);
    double MassFlow(double thrust, double isp);                      // ṁ = F/(Isp·g0)
    double ThrustFromMassFlow(double massFlow, double isp);          // F = ṁ·Isp·g0
    double BurnTime(double propellant, double massFlow);
    double ThrustToWeight(double thrust, double mass, double gravity);
    double Acceleration(double force, double mass);                  // a = F/m
}
static class TransferCalculator {
    HohmannTransfer Hohmann(double mu, double r1, double r2);        // Δv1, Δv2, сумма, время, a
    double HohmannPhaseAngle(double mu, double r1, double r2);       // угол цели при старте
    double SynodicPeriod(double t1, double t2);
    double TimeToPhaseAngle(double currentPhase, double requiredPhase, double n1, double n2);
    double DepartureDeltaV(double muPlanet, double rPark, double vInfinity);   // из круговой орбиты
    double CaptureDeltaV(double muPlanet, double rPark, double vInfinity);
}
static class RocketDesignAnalysis {
    RocketDesignReport Analyze(RocketConfiguration c, double surfaceGravity, double requiredDeltaV);
}   // сухая масса, топливо, стартовая масса, тяга, Isp, ṁ, Δv по ступеням, TWR, предупреждения
sealed class FlightRecorder { /* MaxAltitude, MaxSpeed, Distance, FlightTime, DeltaVExpended, GravityLoss, DragLoss, SteeringLoss */ }
```

Правила:
1. UI, Академия, ангар, навигатор **вызывают эти функции**; формулы не дублируются нигде.
2. `RocketState` сам использует `RocketEquations` — то есть калькулятор в Академии и реальная ракета считают одним кодом.
3. Всё в СИ (кг, м, с, Н, К). Перевод единиц — только в `UnitFormatter`.
4. Новые игровые данные (модули, образцы, профиль) — сериализуемые классы в ядре; Unity-обёртки только хранят ассеты.

## 7. Агенты и ответственность (владение файлами)

Каждый агент правит только «свои» файлы; общие файлы (`FreeFlightSimulation`, `RocketState`, bootstrap, HUD) меняет **только главный агент** при интеграции.

| Агент | Зона | Владеет |
|---|---|---|
| 1 Rocket Physics | физика ракеты, Level A/B | `Core/Flight/Rocket*.cs`, `Core/Physics/*` |
| 2 Inventory & Economy | модули, профиль, магазин, сохранения | `Core/Economy/*`, `Core/Persistence/Player*` |
| 3 UI/UX | окна: статистика, ангар, магазин, академия, навигация | `Runtime/UI/*` (кроме `FlightHUD` — интеграция) |
| 4 Orbital Navigation | перелёты, окна, план | `Core/Navigation/*` — **только через функции ядра агента 1** |
| 5 Planet Environment | рельеф, озёра, опасности поверхности | `Core/Procedural/*`, `Runtime/Planets/*` |
| 6 Research & Sampling | образцы, оборудование | `Core/Science/*` |
| 7 Graphics | шейдеры, материалы, модели, частицы | `Shaders/*`, `Runtime/Environment/*` |
| 8 Integration & QA | тесты, регрессия, производительность | `Tests/*`, `Tools/*` |

Работа агентов ведётся последовательно по milestone; параллельно — только независимые части с непересекающимися файлами
(например, реализация и независимые проверочные тесты одного API).

## 8. Стратегия интеграции и проверки (Definition of Done)

1. Интерфейс фиксируется в этом документе до реализации.
2. Ядро: `dotnet test Tools/CoreTests/SpaceSim.Core.Tests` — все тесты зелёные.
3. Unity-слой: `dotnet build Tools/UnityStubCheck` — 0 ошибок.
4. **Компиляция в настоящем Unity** — через `SpaceSimBridge` (`refresh`, лог Editor без `error CS`).
5. **Проверка в игре** — Bridge: `play`, сценарий команд, `status`, `screenshot`, затем `stop`.
6. Отчёт по milestone: функции, изменённые/новые файлы, тесты, ограничения, что осталось.
7. Если что-то нельзя проверить — это явно указывается в отчёте.

## Отчёт Milestone 1 — Единая физика ракеты (2026-11-03)

**Реализовано**
- `RocketEquations` (Level A): Циолковский и обратные задачи, ṁ ↔ F, время работы, TWR, a = F/m. `RocketState` переписан на них — один код для ракеты, ангара, Академии.
- `TransferCalculator` (Level A): Гоман, фазовый угол, синодический период, время до окна, выход/захват (patched conics).
- `RocketDesignAnalysis` (Level A): массы, тяга, Isp, ṁ, Δv и TWR по ступеням, предупреждения CannotLiftOff / InsufficientDeltaV / … .
- `FlightRecorder` (Level B): время полёта, путь, макс. высота/скорость/q/перегрузка, израсходованный Δv и потери (гравитация, сопротивление, управление) относительно поверхности.
- Активный участок интегрируется RK4, баллистический — Velocity Verlet.
- HUD ракеты: TWR (макс.) из ядра, Δv идеальный остаток / израсходовано / потери.
- Bridge: `test editmode|playmode`, `errors`, `scene` — проверка в настоящем Unity без участия игрока.

**Проверка (фактически выполнена)**
- `dotnet test`: 132/132 (82 прежних + 4 FlightRecorder + 46 независимых тестов агента QA по справочным значениям: LEO→GEO, Земля→Марс, фазовый угол 44.4°, синодический период 780 сут, Циолковский, Merlin ṁ).
- Unity 6000.0.40f1: компиляция без ошибок; EditMode Test Runner 138/138; PlayMode 1/1.
- Живой полёт через Bridge: старт, наклон на восток, 12 км за 87 с; баланс 996 м/с = 481 (прирост) + 502 + 11 + 3 (потери).

**Известные ограничения**
- Ориентация меняется мгновенно (нет вращательной динамики); масса постоянна внутри подшага.
- Баланс потерь на вращающейся планете приближённый (не учитываются кориолисовы члены).
- Конфигурация ракеты всё ещё одна, в инспекторе `FlightBody` — модули появятся в M2.

**Осталось (следующий milestone — M2 Ангар)**: каталог модулей, `RocketBlueprint` → `RocketConfiguration`, окно ангара, совместимость, статистика в реальном времени из `RocketDesignAnalysis`.

## Отчёт Milestone 2 — Ангар и сборка ракеты (2026-11-03)

**Реализовано**
- Ядро (`SpaceSim.Vehicles`): `ModuleDefinition` (6 категорий), `ModuleCatalog` (20 модулей; 5 помечены «магазин» для M3),
  `RocketBlueprint` (ступени: двигатель × N + баки с заливкой; отсек полезной нагрузки), `BlueprintCompiler` → `RocketConfiguration`
  + `VehicleCapabilities` + замечания; `MissionRequirements` (идеальные Δv: подъём, орбита, уход) на центральных функциях.
- Последствия вместо запретов: переливка → заливается ёмкость; чужое топливо → мёртвый груз; >9 двигателей → 9;
  вакуумный двигатель на 1-й ступени, TWR < 1, нехватка Δv — объясняются (Level A: «без потерь»).
- Модули влияют на игру: масса каждого модуля уменьшает Δv; «Анализ орбиты» (O) требует НК-1; защита/пробоотборники — уровни для M6.
- Окно «Ангар» (агент UI): каталог по категориям с характеристиками, сборка ступеней, ползунки топлива, живая статистика
  (сухая/топливо/стартовая масса, тяга у поверхности и в вакууме, Isp, ṁ, TWR, Δv по ступеням, время работы), возможности полёта,
  предупреждения; «Применить» строит новую ракету на площадке. Открывается кнопкой «АНГАР» / B только на площадке; пока открыт — камера и горячие клавиши на паузе.

  двигатели, полезная нагрузка, блокировки, требования миссий).
- Unity: компиляция без ошибок; EditMode 151/151; PlayMode 1/1.
- В игре через Bridge: окно ангара открывается и отрисовывается (скриншот); применение проекта (+НК-1, +бак K-10) → масса +10.92 т,

**Известные ограничения**
- Ангар не проверялся «руками» мышью в Unity (кнопки/ползунки) — только отрисовка и программное применение проекта.

**Осталось (M3)**: профиль игрока (валюта, купленные модули), магазин, продажа образцов, версионируемые сохранения проекта ракеты.
